# Dependency graph visualizer

## Общее описание
Инструмент визуализации графа зависимостей пакетов Alpine Linux (apk).
Параметры задаются в TOML-файле. Менеджеры пакетов и сторонние
библиотеки не используются.

## Параметры (config.toml)
- package - имя анализируемого пакета
- repository - URL репозитория или путь к файлу тестового репозитория
- test_mode - режим работы с тестовым репозиторием (true/false)
- version - версия пакета
- ascii_tree - вывод зависимостей в формате ASCII-дерева (true/false)
- max_depth - максимальная глубина анализа (целое число, не меньше 0)

## Сборка и тесты
Требуется Python 3.11 или новее.

    python -m unittest discover -s tests -v
    run.bat

## Примеры использования

## Реализованные этапы

1. Чтение и проверка TOML-конфигурации.
2. Получение прямых зависимостей пакета Alpine Linux
   для указанной версии.

Этапы 3–5 не реализованы.

## Запуск этапа 1

Вывести настройки без обращения к сети:

    python src\main.py --show-config

## Запуск этапа 2

Получить прямые зависимости:

    run.bat

Для этого режима требуется подключение к интернету.
В config.toml необходимо указать test_mode = false.

## Как получаются данные

Программа скачивает APKINDEX.tar.gz стандартным модулем urllib.
Модули gzip и tarfile читают архив в памяти, без извлечения на диск.

В текстовом индексе используются поля:
- P — имя пакета;
- V — версия пакета;
- D — прямые зависимости.

Поиск выполняется по точному имени и версии.
Ограничения версий зависимостей сохраняются.
Конфликты с префиксом ! не выводятся как зависимости.
Требования so: выводятся без подбора пакетов-провайдеров.

Менеджеры пакетов и сторонние библиотеки для получения
зависимостей не используются. Подпись индекса не проверяется.

## Назначение файлов

- src/main.py — запуск программы и вывод результата;
- src/config.py — чтение и проверка конфигурации;
- src/apk.py — скачивание и разбор индекса Alpine;
- tests/test_config.py — проверки конфигурации;
- tests/test_apk.py — проверки обработки индекса.

## Ограничения текущей версии

test_mode, ascii_tree и max_depth читаются из конфигурации.
Работа с тестовым графом, обход с ограничением глубины
и построение ASCII-дерева в этап 2 не входят.

Индекс содержит только версии, доступные в выбранном репозитории,
а не полную историю выпусков пакета.
